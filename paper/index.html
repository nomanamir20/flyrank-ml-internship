Machine Learning for Prioritizing Declining Keyword-Article Content for Human Review

A decision-support approach for ranking keyword-article content that shows signals associated with decline.

Section 1

Abstract

This study investigates whether machine learning can help prioritize keyword-article content that shows signals of decline so that human reviewers can focus their attention on the highest-priority cases.

Using the anonymized FlyRank internship dataset, the analysis frames decline detection as a binary classification and ranking problem and evaluates a learned model using client-grouped validation to reduce the risk of client-specific leakage.

On the held-out validation set of 2,789 rows from 5 clients, the validated model achieved Precision@20 of 0.9500, Precision@50 of 0.9600, Precision@100 of 0.9600, ROC-AUC of 0.6696, and Average Precision of 0.8568.

The resulting scores are used to create a ranked review queue and action playbook rather than to automatically rewrite, delete, redirect, or publish content.

The results support the use of the model as a decision-support signal for human review, while the model's limitations, validation scope, and non-causal interpretation require contextual inspection before any content decision is made.

Section 2

Introduction / Problem Statement

Search-driven content can decline in performance for many reasons, including changes in search demand, competition, content freshness, user behaviour, and changes in the search environment. For a large content inventory, manually inspecting every article is inefficient.

This project investigates whether a machine-learning ranking system can help identify which keyword-article content items should receive human attention first.

The problem is therefore framed as a binary classification and prioritisation task. The target indicates whether an observed content item belongs to the declining class, while the model produces a score that can be used to order items for review.

Research question: Can a machine-learning model provide a useful ranking signal for prioritizing keyword-article content associated with observed decline, while avoiding leakage and maintaining a human-review workflow?

The intended user of the resulting system is a human SEO, content, or analytics reviewer who needs a practical way to decide which content deserves investigation first.

The system is deliberately positioned as decision support. It does not automatically rewrite content, delete pages, redirect URLs, or make production decisions.

Feature groups

The modelling workflow uses 40 model features consisting of 29 numeric features and 11 categorical features.

Excluded variables

The following variables are deliberately excluded from the predictive feature set:

  • trend_direction
  • trend_pct
  • is_declining_label
  • client_id
  • content_id

Trend variables are excluded because they directly encode information closely related to the observed target. The target itself is excluded because it is the prediction label. Client and content identifiers are retained for validation or identification but are not used as predictive features.

Public-safety framing

The public analysis is based on anonymized data. No client names, private domains, private URLs, private queries, or other identifying search information are included in the research artifact.

Section 4

Methodology

Problem framing

The task is treated as both binary classification and ranking. The positive class represents content associated with observed decline. The model score is then used to rank candidate content for human review.

Label definition

Target variable: is_declining_label

  • 1 = declining
  • 0 = not declining

Assumptions

  1. The task is treated as binary classification and ranking.
  2. The model is used for decision-support and human review, not automatic content changes.
  3. Rows represent keyword-article content items in the selected analysis lane.
  4. Client IDs are used for grouped validation only and are not model features.
  5. Content IDs are identifiers only and are not model features.
  6. The observed label is treated as an evaluation outcome, not as a causal explanation.

Leakage controls

The methodology explicitly removes the target, direct trend indicators, and identifiers from the predictive feature set. This prevents the model from simply learning the answer from variables that directly encode the outcome or identity.

Leakage check: trend_direction, trend_pct, is_declining_label, client_id, and content_id are excluded from model features.

Validation design

Client-grouped validation is used so that validation clients do not overlap with training clients. This provides a stronger test of whether the ranking signal can transfer beyond the specific client groups used during training.

The final validated evaluation contains 2,789 held-out rows from 5 clients, with zero client overlap between training and validation groups.

Intended model use

The resulting score is a prioritisation signal for human review. It is not treated as causal evidence and does not automatically trigger content changes.

Interpretation

The top-ranked portion of the model's queue contains a high proportion of observed declining items. Precision@20, Precision@50, and Precision@100 therefore provide a direct measure of how useful the ranking is when reviewers have limited capacity and need to inspect the highest-priority content first.

ROC-AUC and Average Precision provide broader measures of ranking quality across the validation set. These metrics should be interpreted alongside the top-k precision measures because the practical use case is prioritisation rather than simply producing a binary yes/no classification.

Important: These results describe performance on the evaluated client-grouped validation split. They should not be presented as proof that the model will perform identically on every future client, content population, or search environment.
Section 6

Limitations & Honest Framing

The results should be interpreted as a prioritisation and decision-support analysis rather than as causal evidence about why an article declines. The model identifies patterns associated with the observed decline label, but it does not establish that any individual feature caused the decline.

Dataset limitations

  • The analysis uses the available FlyRank ML Internship dataset and the selected keyword-article analysis lane. Results should therefore not be assumed to generalise to every content type, website, industry, or search environment.
  • The dataset contains anonymized production search data. Client and content identifiers are retained only for grouping and identification purposes and are not used as predictive model features.
  • Some variables contain missing values. These missing values may reflect the underlying data-generation process and are not necessarily random.

Methodological limitations

  • The target variable represents an observed decline outcome. It should not be interpreted as a direct measure of content quality or as proof that a specific intervention will reverse the decline.
  • Client-grouped validation reduces the risk of client overlap between training and validation data, but it does not guarantee performance on completely different future datasets.
  • The model is evaluated as a prioritisation signal. A high score means that an item deserves attention; it does not mean that the item definitely requires a particular content change.
  • Historical search-performance patterns may change as search engines, user behaviour, competitors, and content environments change.

Leakage and interpretation safeguards

Variables that directly represent the observed trend or target were excluded from the model features. In particular, trend_direction, trend_pct, and is_declining_label were excluded. Client IDs and content IDs were also excluded from model features.

Honest claim

The strongest defensible claim from this work is that the evaluated model provides a useful data-driven prioritisation signal for identifying keyword-article content items that match patterns associated with observed decline.

It should be used to support human investigation and prioritisation, not as an automated decision-maker or causal explanation.

Practical interpretation: A model score should answer “Which content should we investigate first?” rather than “What caused this content to decline?”
Section 7

Ranked Recommendations

The model output is translated into a practical review workflow. Recommendations are ranked by the expected value of human investigation rather than by an assumption that every high-scoring article needs the same intervention.

Priority 1

Investigate the highest-ranked decline candidates first

Start with the highest-scoring items in the ranked queue. Confirm that the observed decline is real and that sufficient recent data exists before taking action.

Priority 2

Check search intent and current SERP context

Review whether the search intent has changed and whether the current search-result environment still matches the article's purpose. A model score alone cannot determine whether an article should be refreshed.

Priority 3

Inspect content freshness and completeness

Check whether important information is outdated, missing, inaccurate, or no longer aligned with the user's likely needs.

Priority 4

Investigate external explanations

Consider seasonality, changes in demand, competitive movement, search-environment changes, and other external factors before attributing the decline to the content itself.

Priority 5

Apply changes only after human review

The model should inform a decision rather than make the decision. Publishing, rewriting, deletion, redirects, or other production changes require contextual human judgement.

Human-review workflow

Model ranking → Human inspection → Contextual checks → Decision → Manual action

No-go cases

The system should not automatically perform publishing, article rewriting, content deletion, URL redirects, search-intent changes, SEO metadata changes, business-critical decisions, or production changes.
