01 / Abstract

Title + Abstract

Can machine learning help prioritize keyword-article content that is likely to experience declining performance?

Abstract

This study investigates whether historical content, search, engagement, and freshness signals can be used to prioritize keyword-article content for human review when an article is associated with declining performance.

Using the FlyRank ML Internship dataset, the analysis focuses on 27,207 keyword-article rows from a larger 30,000-row dataset and formulates the task as a binary classification and ranking problem.

The methodology excludes identifiers and variables that would directly expose the target or observed trend, including trend_direction, trend_pct, client_id, content_id, and the target label itself. Validation uses client-grouped splits so validation clients do not overlap with training clients.

The validated model achieves Precision@20 of 0.9500, Precision@50 of 0.9600, and Precision@100 of 0.9600. It achieves ROC-AUC of 0.6696 and Average Precision of 0.8568.

These results support using the model as a decision-support ranking system for prioritizing human investigation. The score is not treated as causal evidence and does not independently justify rewriting, deleting, redirecting, or publishing content.

02 / Introduction

Introduction / Problem Statement

Content teams often have more articles to review than they can realistically investigate manually. A decline in search or engagement performance may indicate that an article deserves attention, but reviewing every content item with equal priority is inefficient.

This project asks whether historical signals can be transformed into a ranking score that helps a human reviewer decide which keyword-article rows deserve attention first.

Research question Can a machine-learning model rank keyword-article content so that human reviewers encounter a high proportion of declining items near the top of the queue?

The project is therefore framed as a decision-support problem, rather than an autonomous SEO optimization system.

Input

Historical content, search, traffic, engagement, freshness, and competition-related signals.

Output

A ranked queue of content candidates for human review.

Data categories

The available variables cover several signal families, including search demand, competition, content characteristics, traffic, engagement, freshness, position, and AI-related traffic indicators.

Exclusions

  • trend_direction was excluded because it directly describes the observed trend.
  • trend_pct was excluded because it directly represents trend movement.
  • is_declining_label was excluded from model features because it is the target.
  • client_id was excluded from model features to prevent client identity from becoming a predictive shortcut.
  • content_id was excluded because it is an identifier rather than a meaningful predictive signal.
Public-safety approach The research artifact does not publish client names, private URLs, private search queries, or other identifying information.
04 / Methodology

Methodology

Task formulation

The task is treated as binary classification followed by ranking. The positive class represents content associated with the observed declining outcome.

Component Definition
Target is_declining_label
Positive class 1 = declining
Negative class 0 = not declining
Use case Human-review prioritization
Validation Client-grouped split

Feature design

The initial feature set contains numeric and categorical variables derived from the available search, content, traffic, engagement, and freshness signals. Target, trend, and identifier variables are excluded before model training.

Leakage controls

  • Target variable excluded from model features.
  • Direct trend variables excluded.
  • Client identity excluded from model features.
  • Content identity excluded from model features.

Validation design

Validation is performed at the client-group level. This means clients assigned to validation are not simultaneously present in the training group. The purpose is to test whether the ranking signal can generalize beyond the clients used for training.

DATASET | v Keyword-article lane | v Feature preparation | +--------------------+ | | v v Training data Validation data grouped by client grouped by client | | v v Model training Evaluation | | +---------+----------+ | v Decline score | v Ranked queue | v Human review

Interpretation principle

The observed label is used for evaluation and ranking. It is not interpreted as proof that any particular feature caused the decline.

Validation population

The validated evaluation set contains 2,789 rows from five validation clients, with zero client overlap between training and validation.

Important interpretation High top-k precision does not mean that the model perfectly predicts decline for every content item. ROC-AUC is materially lower than the top-k precision, showing that the strongest practical value is in prioritization near the top of the queue rather than perfect global classification.
06 / Limitations

Limitations & Honest Framing

The results should be interpreted as evidence that the model can support prioritization under the evaluated validation design. They should not be interpreted as proof of causality or as a fully autonomous SEO system.

Key limitations

  1. The evaluation is based on the available dataset release and may not represent every possible content or client environment.
  2. The observed decline label describes an outcome; it does not explain why the decline happened.
  3. The ROC-AUC result of 0.6696 indicates that global discrimination is substantially less perfect than the very strong top-k precision results.
  4. Search behavior, seasonality, competitor changes, algorithm updates, and external events may affect content performance.
  5. Model performance may change when future client, content, or feature distributions differ materially from the validation population.
  6. Human review remains necessary before making content or SEO changes.
No autonomous publishing The model should not automatically rewrite, delete, redirect, publish, change search intent, modify SEO metadata, or make business-critical decisions.

A high score should be interpreted as "review this item earlier", not "change this item automatically."

Final note

From prediction to responsible review

The central output of this project is not an automated content-change system. It is a ranked decision-support queue that helps a reviewer decide where to spend attention first.

The strongest evidence is concentrated in the top of the ranking, while the broader discrimination metrics show that the model should not be treated as infallible. The appropriate workflow therefore combines machine ranking with human investigation and contextual judgment.

Responsible-use principle Use the model to decide what to investigate first, not what to change automatically.
